# v3.0.8-praktimarc.5

Release date: 2026-10-19

This release adds a public RouterOS word-level execution interface for API diagnostics,
without changing the existing pseudo-command parser, transport, credentials,
session lifecycle, or behavior of `execute(String)`. The motivation is to compare
RouterOS server query variants (for example, modern CAPsMAN remote-CAP filters)
without assuming that the client library parses them equivalently.

## Public additive API

```java
String tag = connection.executeWords(
    java.util.List.of(
        "/interface/wifi/capsman/remote-cap/print",
        "?base-mac=D0:EA:11:8A:2F:9B"),
    listener);
```

The first word is the absolute RouterOS API command. Following words are
transmitted **without** pseudo-command parsing, quoting, normalization or
client-side filtering, and in the exact order provided. The transport
adds the connection-managed `.tag` word and a zero-length sentence terminator,
and encodes each UTF-8 word using the native RouterOS word-length format.

Example alternate syntax for bug reports:

```java
connection.executeWords(
    java.util.List.of(
        "/interface/wifi/capsman/remote-cap/print",
        "?=base-mac=D0:EA:11:8A:2F:9B"),
    listener);
```

The implementation validates that the word list is not empty, that words are
nonempty strings without embedded NUL bytes, that the first word is an
absolute command path, and that callers do not supply their own `.tag=`.
`ApiConnection` provides a default unsupported implementation to retain
compatibility with third-party subclasses.

## Protocol and compatibility

- Works on the existing authenticated API connection, including TLS when the
  caller initially used a TLS socket factory. There is no separate connection.
- Uses the existing write lock, command tagging, response listener routing,
  cancellation, and fatal-connection failure semantics.
- `execute(String)` and `execute(String, ResultListener)` retain their
  historical parser behavior.
- This is an expert-only API that can send destructive commands; use trusted
  inputs and do not log secrets in protocol words.
- This is UTF-8 text-word access, not arbitrary binary-word access.
- Java baseline remains Java 11.

## Verification

The Java 11 Maven CI and exact-wire loopback tests passed on the implementation
that entered the release preparation:
[CI of merged implementation](https://github.com/praktimarc/mikrotik-java/actions/runs/38744601656).

The regression tests verify the exact outgoing RouterOS API words (including
the uncommon `?=base-mac=...` variant), command-word order, automatic tag,
and successful tagged `!re` and `!done` callbacks. A separate full Maven
verification runs on the release commit before the release workflow creates
the immutable tag and publishes the GitHub artifacts.

## Publication

The GitHub release contains the main JAR, source JAR, and Javadoc JAR.
Maven Central deployment remains a separate signed, manually approved release
process: the Central staging workflow validates the exact release tag,
rebuilds the JAR, and compares compiled class files byte-for-byte against the
GitHub Release artifact. `autoPublish=false` remains set; final publication
requires review in the Central Portal. Do not republish or replace an existing
version.
