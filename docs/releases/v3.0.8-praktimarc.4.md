# v3.0.8-praktimarc.4

Release date: 2026-10-01

`3.0.8-praktimarc.4` is a focused compatibility follow-up to `3.0.8-praktimarc.3`. It closes a gap in the listener-based command API: terminal RouterOS `!done` properties are now available to asynchronous and other `ResultListener` consumers instead of being visible only through the internal synchronous `ret` handling.

## Why this release exists

The public listener API previously ended a successful command with only:

```java
void completed();
```

RouterOS can attach properties to the terminal `!done` sentence, most importantly `=ret=...` for commands that return an identifier or another terminal value. The synchronous `execute(String)` implementation already preserved `ret` through an internal special case, but callers using `execute(String, ResultListener)` could not observe it. That made it impossible for a higher-level API to use one listener-based pipeline for both synchronous and asynchronous commands without losing terminal metadata.

## Public API addition

`ResultListener` now has an additive default method:

```java
void completed();

default void completed(Map<String, String> completion) {
    completed();
}
```

Existing listener implementations therefore do not need to change. A listener that wants terminal metadata can override the map-based method.

Example:

```java
con.execute("/interface/bridge/add name=bridge-api", new ResultListener() {
    @Override
    public void receive(Map<String, String> result) {
    }

    @Override
    public void error(MikrotikApiException ex) {
        ex.printStackTrace();
    }

    @Override
    public void completed() {
    }

    @Override
    public void completed(Map<String, String> completion) {
        System.out.println("Created object: " + completion.get("ret"));
    }
});
```

## `!done` property handling

The response parser now preserves all normal `=name=value` attributes from `!done`, not just `ret`.

For example, a terminal sentence containing:

```text
!done
=ret=*A
=foo=bar
=empty=
.tag=17
```

is delivered to `completed(Map<String, String>)` as the equivalent of:

```text
ret   -> *A
foo   -> bar
empty -> ""
```

The command `.tag` remains internal routing metadata and is deliberately not included in the completion map. The map supplied to consumers is unmodifiable.

A plain `!done` without attributes produces an empty map.

## Compatibility

- Existing `ResultListener` implementations remain source-compatible because the new callback is a Java default method.
- On the Java 11 baseline, existing compiled implementations remain compatible with the additive default interface method and continue to reach their existing `completed()` callback.
- The dispatcher removes the command registration before invoking the terminal completion callback, preserving the terminal/listener-lifecycle guarantees introduced in `.3`.
- The synchronous `execute(String)` API keeps its established result shape: `!done =ret=...` still adds a result containing only `ret`; other terminal properties are not injected into the legacy synchronous result list.
- Error, cancellation, binary download, transport, and connection-loss semantics are unchanged.

## Downstream facade impact

This release provides the missing low-level primitive required by `praktimarc/mikrotik-facade`: sync and async operations can now share the same listener-based command pipeline while retaining RouterOS terminal return values and future `!done` properties.

The facade therefore does not need a separate synchronous path or a hard-coded workaround for `ret`.
